# ② 表征

> 把传感器数据变成决策层能直接用的形式。**这一环的产出是一个坐标系统，不是一张图。**

## 这一环要回答什么

相机给的是图像，激光雷达给的是点云，而决策需要的通常是"我周围有什么、在哪、往哪动"。中间这一步就是表征。

关键问题只有一个：**在哪里做多传感器的融合。**

## 智驾侧：为什么要 BEV

两条路线，本质区别是"在哪个空间融合"：

1. **显式体素路线**（Lift-Splat-Shoot 是原型）：每个像素预测一个深度分布，把特征"抬"（lift）到一个锥形射线束上，再"泼"（splat）到 BEV 网格里做池化。融合发生在 BEV 网格里，是一个求和。
2. **隐式查询路线**（BEVFormer / DETR3D 一派）：预设一组 BEV query，让它们去多个视角的图像特征里采样（可变形注意力），融合发生在注意力里。

**为什么非要换空间**：同一根杆子被前相机和左前相机同时看到。在图像空间里，它是两个坐标，要先解"这两块像素对应同一个物体"——一个跨视角匹配问题。在 BEV 里，它是同一个格子，融合退化成相加。这是一次从"匹配问题"到"累加问题"的降级，也是 BEV 成为主流的原因。

代价：Lift-Splat-Shoot 依赖每个像素的深度估计，而深度是真值里最贵、最不准的一项；深度误差会沿射线传播到 BEV。

## 智驾侧：为什么必须有时序

单帧给不出速度，也给不出被遮挡物体的存在。遮挡帧上单帧检测可能**完全没有输出**，而时序模型可以利用前后帧的连续性补出来。这不是精度优化，是**可用性问题**——一个在遮挡时失去全部感知的系统的行为是不可预测的。

## 具身侧

不像智驾那样收敛。可选项包括：

- **RGB 直接进 VLM**——当前 VLA 的主流：不做显式 3D 重建，让预训练的视觉编码器自己学空间表征。
- **深度 / 点云**——精度高，但传感器贵、标定难、在反光/透明物体上失效。
- **VLM 的中间 token 作为共享表征**——π0 一派的做法：视觉 token 和语言 token 走同一个 Transformer，动作头从这些 token 上接出来。

**两条路的差别在于"显式几何"要不要保留**：智驾因为要和地图、规控对接，必须落到一个共享的几何空间；具身因为直接出动作，可以把这个空间交给模型自己学。
