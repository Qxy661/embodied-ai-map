# ③ 决策

> 这一环问题是：**模型什么时候算、算什么、算多快。**

## 这一环要回答什么

决策层拿到表征，要输出动作。看似简单，但这个领域几乎所有的架构争论都发生在这一环：

- 一个模型端到端出动作，还是拆成感知/预测/规划几段？
- 动作是**一步一步出**，还是**一次性出一段**？
- 动作是**连续量回归**、**连续场积分**，还是**离散 token 解码**？
- 模型算得慢，**手上的动作从哪来**？

## 端到端 vs 两段式：一个来回摆的钟

这条轴在智驾和具身两边**同时**摆，只是节奏不同。

**智驾**：模块化管线（感知 → 预测 → 规划 → 控制）统治了很多年，因为每一段可解释、可单独验证、可局部修复。后来端到端方案出现，理由是模块间的接口（"预测"输出的轨迹）本身是个信息瓶颈，而且误差会逐段累积。再之后又出现回归两段式的讨论——因为纯端到端难以调试、难以加规则兜底，且对长尾行为的控制力弱。

**具身**：VLA 直接端到端出动作是当前主流，但**分层**（慢脑 / 快脑）在工程上几乎是必需的——这不是架构偏好，是延迟的硬约束（见 ⑤ 环）。

两边摆动的驱动力是同一个：**端到端换来性能上限，模块化换来可调试性和可控性。** 谁能赢取决于哪一边的瓶颈更紧——而瓶颈会随规模和数据量移动。

## 动作生成范式：两条轴的同步演化

**这是本图三条跨域收敛之一。**

具身的动作头与智驾的轨迹输出，在**同一时间轴上同构演化**：

| 阶段 | 智驾轨迹 | 具身动作头 |
|---|---|---|
| 回归 | 直接回归轨迹点 | 直接回归动作（MSE） |
| 生成式 | 扩散 / 流匹配生成轨迹 | 扩散 / 流匹配生成动作 chunk |
| 离散/世界模型 | 世界模型 + 搜索 | 离散扩散 / AR token |

这不是谁抄谁，而是**同一个数学问题逼出来的同一串解法**：多峰的动作分布不能用单峰回归拟合。回归会收敛到各个模态的**均值**——而均值往往是一个既不安全也不可行的动作（比如"左转"和"右转"的平均是"直行撞上去"）。

③-02（流匹配）和 ③-03（AR token）是这条演进里当前并存的两条路线：**少步并行积分** vs **多步串行解码**。

## 频率错配：这一环的起点

在讨论"用什么方法生成动作"之前，先有一个更基础的问题：**控制环要 1 kHz，模型只能跑 20 Hz。中间那 980 个周期，动作从哪来？**

这就是 ③-01 讲的频率错配，也是整个决策环的现实约束。它派生出两个概念：

- **动作分块**：一次推理出一个 chunk，中间靠开环执行撑住。代价是 chunk 内的动作越来越陈旧。
- **实时分块（RTC）**：在旧 chunk 还没执行完时就开始推理下一个，并把"已执行的动作"作为前缀条件喂进去，让接缝对得上。

**这一环的技术演进，本质上是围绕"陈旧"这个约束在找出路。**
