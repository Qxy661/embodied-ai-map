# 智驾 × 具身：一张可运行的领域地图

> 这不是一份文档。这是一堆**能跑的实验**，外加一条把它们串起来的线索。

大多数综述的问题是：**你没有理由相信里面的数字。**

读者看到"动作分块显著降低误差"，无法判断那是作者的直觉、某篇论文的结论、还是实验的结果。数字在文档里是自由的——可以来自任何地方，可以四舍五入到任何方向，可以在改稿时悄悄漂移。这是文档这一形式的固有缺陷，不是作者的道德问题。

这个仓库把那条缝焊死了。做法很小，但后果很大：

```
map/03-decision/01-frequency-mismatch/
├── run.py          ← 唯一的数字来源
├── results.json    ← run.py 的产物，提交进仓库
├── README.md       ← 正文。里面的每个数字必须来自 results.json
└── meta.yaml       ← 层级、参与度、字面量白名单
```

**每个块正文里出现的数字，都由 `scripts/check_numbers.py` 逐个回溯到 `results.json`。** 对不上就构建失败。想改数字？回去改代码、重跑。想引论文里的数？必须在那一行标 `!CITE`，明确说"这是别人测的，不是我测的"。

于是"可信"不再取决于读者是否相信作者，而变成一个可以执行的检查。

## 一、范围：智驾 与 具身，是同一个问题吗

这张地图只覆盖两者的**交集**——不是并列介绍两个领域，而是找出它们共享的那套工程结构。

结论是：**交集比想象中大，但有一处根本性的不同。**

**共享的部分**：都是一条「感知 → 表征 → 决策 → 执行 → 部署 → 评估 → 回流」的闭环；都受同一条延迟预算支配；都在同一条"端到端 vs 两段式"的轴上反复摆；都收敛到了同一套分层架构。

**不同的部分只有一处，但很硬**：**数据成本结构。**

- 智驾的数据来自车队。车在路上跑，数据是白捡的，**边际成本≈0**，所以可以堆到十亿公里量级。
- 具身的数据要人架设备、摆场景、反复采。**每条都有真金白银的成本。**

这个差异 >99%，它决定了两边所有下游选择：为什么智驾敢上十亿参数端到端而具身普遍用几 B 的 VLA；为什么智驾的评测靠里程而具身靠任务成功率；为什么具身这边"数据效率"是核心议题而智驾那边不是。

**所以这张地图的骨架是共享的七环，而它的重心偏向具身**——因为稀缺的那一侧决定了工程取舍。

## 三、三条跨域收敛

这是这张地图最实质的产出。三条结论都是**独立团队各自收敛到同一个答案**，而不是谁抄谁：

**1. 分层是唯一收敛的架构解。** 一个够大的 VLA 单次推理要几十到几百毫秒，而底层控制要 100–1000 Hz——单层架构撑不住。Figure Helix、NVIDIA GR00T N1、Gemini Robotics 1.5 给出了结构上同构的分层方案（慢脑做语义、快脑做视觉运动、最底层做关节伺服）。

而**行业共识是"不要正面解决延迟"**：不是把大模型加速到 1 kHz（做不到），而是让慢脑算得慢但算得对、让快脑高频地把慢脑的意图补成连续动作。这解释了一个反常现象——**具身推理的延迟要求至今没有定义，因为架构上绕开了它。**

**2. 动作生成范式的演进是同步的。** 具身的动作头（AR token → flow matching → 离散扩散 / 世界模型）与智驾的轨迹范式（回归 → 扩散 → 世界模型）**在同一时间轴上同构演化**。这不是巧合：两者面对的是同一个数学问题——多峰的动作分布不能用单峰回归拟合。

**3. 真正的分野是数据的成本结构**（见第一节）。

## 四、主次判据

一个没有取舍的综述等于没有综述。每个块在 `meta.yaml` 里声明自己的层级：

> **判据：去掉它，工业界今天是不是就做不出产品？**

- **主**——去掉它，今天的产品线就断了。必须单独成块。
- **次**——重要，但可以绕开或延后。可以单独成块。
- **缓**——前沿、有趣、但尚未进入工程实践。**永远不单独成块**，只在主/次块的「边界」或「脉络」里占一句话。

这条规则是硬的。它挡掉的是那种"什么都提一句"的综述——读起来很全，用起来没有抓手。

## 五、怎么跑

只要 numpy 和 PyYAML。不需要 GPU，不需要联网，不需要下载任何权重。

```bash
pip install -e .

python scripts/run_all.py        # 跑全部块，重算每个 results.json
python scripts/check_numbers.py  # 核心检查：正文数字必须能回溯到结果
python -m pytest tests/          # checker 自身的回归测试
```

`check_numbers.py` 的输出是这样的：

```
check_numbers: OK -- 14 block(s), every cited number traced to a run
```

想验证它真的会拦人，就随便改一个块正文里的数字，重跑——它会失败，并指出是哪一行。

## 六、诚实边界

这个仓库有几处刻意的自我限制，写在这里而不是藏起来：

- **七环是我画的，不是标准。** 见第二节。
- **`volatile` 块的检查是弱的。** 少数块测的是活机器（时序、抖动），这些数字**本来就不可复现**——机器不是同一台机器两次。这类块声明 `volatile: true`，检查放宽为近似核对，并且必须声明 `citable:`（正文允许引用的指标）。**这仍然拦不住落在真值附近的编造**，`scripts/check_numbers.py` 的 docstring 里把这个局限写明白了。诚实地承认一个检查的边界，比假装它没有边界更重要。
- **所有块都是机制的模型，不是生产级复现。** 每个块的「边界」段都会说清哪些是假设、哪些是模型不是现实。
- **引用内容一律标 `!CITE`。** 论文和厂商博客的数字不是本项目测的，标出来是为了让你能分清哪些数可以追溯到这里的一次运行。
