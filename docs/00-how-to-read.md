# 怎么读这个仓库

## 一句话

`map/` 下面每个目录既是**一章文档**，也是一个**可运行的实验**。正文里的数字不是写上去的，是跑出来的。

## 块的结构

```
map/<环>/<NN-名字>/
├── run.py          ← 唯一的数字来源。numpy + 标准库。
├── results.json    ← run.py 的产物。提交进仓库，是正文数字的凭据。
├── README.md       ← 正文：直观 → 机制 → 边界 → 脉络
└── meta.yaml       ← 层级、参与度、字面量白名单
```

`map/<环>/README.md`（环目录本身）是**非块**：它装着这一环里**无法用自测实验证明、只能引用**的内容——架构史、行业收敛、协议规范。它没有 `results.json`，也不参与数字核对。

## 核心机制

`scripts/check_numbers.py` 逐个核对：**块正文里的每个数字，必须是 `results.json` 里某个数的正确舍入。**

三种放行：

| 方式 | 含义 |
|---|---|
| 匹配 `results.json` | 本项目实测/算出来的 |
| 该行带 `!CITE` | 引用论文或厂商，**不是**本项目测的 |
| 在 `meta.yaml` 的 `literals:` 里 | 结构性常量（频率、序数） |

**这个设计解决的是文档的固有缺陷**：读者看到"显著降低误差"，无法判断那是直觉、引用还是实测。数字在普通文档里是自由的，可以来自任何地方，可以在改稿时悄悄漂移。这里不行。

自己验证一下它真的会拦人：

```bash
python scripts/check_numbers.py          # OK
# 随便改一个块 README 里的数字，再跑一次 → FAILED，并指出是哪一行
```

## 三种参与度

`meta.yaml` 的 `engagement` 字段说明这个块和外部世界的关系：

- **`depend`**——依赖某个外部包（从 PyPI 装）。读代码时要意识到有外部依赖。
- **`adapter`**——只读代码、不装包，复现其关键逻辑。
- **`self`**——完全自测，不依赖任何外部实现。

**全部块都是 `self` 或 `adapter`。** 这个仓库不需要 GPU、不需要联网、不需要下载权重——一个能被读者真正跑起来的综述，才是有用的综述。

## `volatile` 块：一个诚实的让步

有两三个块测的是**活机器**（时序、抖动）。这些数字**本来就不可复现**——机器不是同一台机器两次。硬要求逐位一致，只会逼出两种结果：要么块被删掉，要么作者开始手写数字。

所以这类块声明 `volatile: true`，核对放宽为近似。**但要理解这个让步的边界：**

- 它**能**抓住凭空编的数字。
- 它**抓不住**恰好落在真值附近的编造。任何基于容差的检查都有这个性质。

所以 `volatile` 块必须额外声明 `citable:`——正文允许引用的指标。**理由不是形式主义**：近似核对的强度由候选集的密度决定。一个块的二三十个指标跨越四个数量级，在它们周围各开一个 1.5 倍的窗口，几乎覆盖整条数轴，什么都拦不住。点名少数几个，检查才有牙齿。

<sub>这不是推演，是这个仓库真的踩过的坑：早期版本对全部指标开 10 倍窗口，一个凭空写的 `7777` 顺利通过。详见 `scripts/check_numbers.py` 的 docstring。</sub>

## 可复现性

```bash
python scripts/check_reproducible.py
```

每个非 `volatile` 块**跑两遍**，比对 `results.json`（忽略 `generated_at_unix`）。不一致就失败。

值得单独一个脚本，是因为"用了种子"这件事**很容易以为做到了、实际没做到**：一个忘了加种子的 `np.random`、一次对 `set` 的迭代（哈希序）、一次读时钟，都会产生一个没人察觉的微小差异——直到读者复现不出正文的数字。

## 阅读顺序

- **顺着环读**：① → ⑦，是完整的综述。
- **跳着读**：每个块的「边界」段独立性最强，可以单独看。
- **只看结论**：每块的「脉络」段一句话接上前后，串起来就是梗概。

## 主次判据

> **去掉它，工业界今天是不是就做不出产品？**

主 / 次 / **缓**。缓级是前沿但尚未进入工程实践的——**永远不单独成块**，只在别的块的「边界」或「脉络」里占一句话。

这条规则挡掉的是那种"什么都提一句"的综述：读起来很全，用起来没有抓手。
