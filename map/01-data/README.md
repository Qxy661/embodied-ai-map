# ① 数据

> 七环之首。**这一环决定了后面六环的天花板。**

## 这一环要回答什么

**不同机器人的动作，怎么放在一起学。**

每个机器人有自己的自由度数量、关节顺序、旋转表示、单位、坐标系。一台 6 自由度机械臂和一台 7 自由度机械臂，同一个"向前伸"的动作，在各自的原始空间里是完全不同的两组数。如果不统一，跨本体的数据就只是一堆互相矛盾的样本。

## 三条统一路线

1. **统一到本体无关的任务空间**——把动作表示成末端执行器位姿（或末端位姿增量），而不是关节角。位姿是物理量，跨本体共享含义。代价：丢了冗余自由度的解（肘部姿态），逆解可能无解或跳变。
2. **统一到离散 token**——把每一维动作切成 bin，动作变成 token 序列，于是可以复用语言模型的全部基建。代价：量化误差不可消除，且各维的 bin 边界仍然是本体相关的。
3. **保留本体特定表示，用掩码处理**——不做统一，而是显式标注每条数据的本体和有效维度，训练时用掩码让模型只学共有维度。保留了精度，代价是模型必须额外学"我现在是哪台机器"。

**主流选择是第 1 条加第 3 条的混合**：动作空间统一到末端位姿，同时保留本体标识让模型知道自己在控制什么。第 2 条在 ③ 环还会再出现一次——它是自回归动作 token 路线的前置条件。

## 规范做法

这一层已经收敛，**不要自己发明格式**：

- **Open X-Embodiment**（跨机构联合数据集）建立了跨本体数据集的聚合规范，并配套了 RT-X 系列模型作为验证。`!CITE`
- **LeRobot / `LeRobotDataset` 格式**（HuggingFace）已经成为具身数据的事实标准交换格式：一个数据集 = 视频 + 状态/动作表 + 元信息。`!CITE`
- 智驾侧对应的是 **nuScenes / Waymo Open Dataset** 的标注规范，以及各家的数据管线约定。

采用既有格式的收益是复合的：工具链、可视化、预训练权重、评测基线全都直接可用。

## 这一环最硬的一条约束

**数据的成本结构，是智驾与具身真正的分野。**

- 智驾的数据来自车队。车在路上跑，采集是副产品，**边际成本≈0**。
- 具身的数据要人架设备、摆场景、反复采。**每条都有真金白银的成本。**

这个差距超过两个数量级，它决定了两边几乎所有的下游取舍：为什么智驾敢堆十亿公里而具身普遍用几 B 的模型；为什么具身这边"数据效率"是核心议题而智驾那边不是；为什么 ⑦ 环（回流）在具身这边分量重得多。

**所以这张地图虽然骨架共享，重心偏向具身——稀缺的那一侧决定工程取舍。**
