# ④ 执行

> 上面所有环的结论，都建立在**底下的环按时到达**这个假设上。这一环就是去检验这个假设。

## 这一环要回答什么

决策层说"往前走 3 厘米"。这句话要变成电机上的电流，中间隔着一整条实时系统。这条链上有两个独立的代价：

1. **时序代价**：这条环能不能按时到达？（→ ④-01）
2. **传输代价**：模块之间的数据怎么过河？（→ ④-02）

两者都是**预算**，都要从总延迟里扣。

## 控制频率的层级

机器人不是一个控制环，是**一串**频率差几个数量级的环：

| 层级 | 典型频率 | 干什么 |
|---|---|---|
| 任务 / 语义 | 1–10 Hz | 理解指令、选子目标 |
| 全身 / 视觉运动 | 50–500 Hz | 协调多关节，跟踪轨迹 |
| 关节伺服 | 500–1000 Hz 以上 | 电流环 / 力矩环 |

**上游的频率直接受下游约束**：慢脑不能在快脑来不及执行时改变主意（见 ⑤ 环的分层）。而且这个层级结构不是设计选择，是**物理约束**——电流环的带宽由电机的电气时间常数决定。

## 实时性的规范做法

工业界在这一层已经收敛，**不要自己发明**：

- **PREEMPT_RT**：Linux 的实时补丁，把内核抢占延迟从毫秒级压到几十微秒级。
- **CPU 隔离**（`isolcpus` / `nohz_full`）：把控制线程绑在不受调度器打扰的核上。
- **`SCHED_FIFO`**：实时调度策略，控制线程抢占所有普通进程。
- **`mlockall`**：锁住内存，防止缺页中断打断控制环。
- 硬件侧：**EtherCAT** 之类的现场总线，靠分布式时钟做到亚微秒级的节点同步。

这一整套是**必需品不是优化项**：④-01 测出通用 OS 上"睡到点"有八成以上的控制周期超预算——那不是一条 1 kHz 的环。

## 通信与中间件

机器人流水线通常是分进程的（崩溃隔离、语言不同、实时性要求不同）。分完之后：

- **中间件**：ROS 2 / DDS 是当前的事实标准，提供了 QoS 策略（可靠性、截止时间、历史深度）和零拷贝传输。
- **共享内存**：`/dev/shm`、POSIX shm、DDS 的 loaned messages，用于绕开序列化和内核拷贝。
- **关键判断**：**不要传图，传结果**。一张 1080p 图的字节数比一帧检测框高好几个数量级（→ ④-02）。
