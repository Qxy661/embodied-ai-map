# 自回归动作 token：离散化的两笔账

> 环 ③ 决策 · 层级 **主** · 证据 `self`

## 直观

要让机器人用上语言模型那套基建——下一个 token 预测、KV cache、teacher forcing，图像文字动作共用一个词表——就得先把连续动作切成 bin。这条路 RT-2、OpenVLA 在走，是主流，不是小众。

切片本身要付钱，而且付得比看上去多。给关节定 256 个格子，格子的宽度不是由"这个动作动得多大"决定的，而是由**编码器的量程**决定的：数据集里出现过的最远位置定下了量程，之后每一次轻微挪动都按这个格宽量化。一个只在中位附近小范围微调的策略，付的是全量程的价。

第二笔账在解码。语言模型一个一个往外吐 token，第 k 个要看前面 k−1 个。动作 token 也一样：一块 50 步的动作要 50 次前向，每一次都吊在上一次的尾巴上。如果模型解码时只读自己的前缀、不再回头看观测，那么前缀里的误差会被后面每一步继承。

这两笔账分开算都不吓人，合起来才决定 256 这个工业默认值到底是不是拍脑袋。下面的结论有一半和我动手前的预期相反，我按测到的写。

## 机制

### 设定

控制 50 赫兹，一个控制步一个 token（自回归的原生用法）。动作按维度归一化到编码器全量程，一条动作维度做 1 赫兹正弦运动——就是 ③-01 里那条目标运动，振幅取量程的 0.4。512 条轨迹，每条跟着走到 128 个 token，动作块长度按 ③-01 的可行边界取 50。

编码器的量程按 RT-2 / OpenVLA 的规矩取数据集极值：位置量程 0.4，增量量程 0.0602。两者之比 6.64，这个比值后面很关键——它决定 delta 分词值不值得做。

两族轨迹都跑，因为第二族推翻了我原本的假设（见第四节）。`periodic` 是单频正弦；`bandlimited` 叠加 5 个不可通约的谐波，轨迹不重复，增量也不重复。两族都归一到同一个峰值振幅，所以位置量程相同，**只有频谱这一个变量**。

### 一、格宽由量程定，不由信号定

均匀量化器在输入分布均匀时，误差 RMS 就是 格宽/√12。实测下来两个方案的差别很有意思：

| N | 绝对格宽 | 绝对实测 RMS | 实测/律 | 增量格宽 | 增量实测 RMS | 实测/律 |
|---|---|---|---|---|---|---|
| 16 | 0.05 | 0.018573 | 1.29 | 0.0075254 | 0.002285 | 1.05 |
| 32 | 0.025 | 0.008855 | 1.23 | 0.0037627 | 0.001106 | 1.02 |
| 64 | 0.0125 | 0.004229 | 1.17 | 0.001881 | 0.000547 | 1.01 |
| 128 | 0.00625 | 0.002034 | 1.13 | 0.000941 | 0.000272 | 1.00 |
| 256 | 0.003125 | 0.000983 | 1.09 | 0.000470 | 0.000136 | 1.00 |
| 512 | 0.0015625 | 0.000481 | 1.07 | 0.000235 | 0.000068 | 1.00 |
| 1024 | 0.00078125 | 0.000237 | 1.05 | 0.000118 | 0.000034 | 1.00 |

**绝对 token 不服从这条律，而且偏得系统性。**N=16 时实测是律值的 1.29 倍，N=256 还有 1.09 倍，一直在往 1 收敛但很慢。原因不是数值问题：正弦在量程两端的驻留时间长（反正弦分布），样本挤在极值附近，误差就集中在 ±格宽/2 上，不再均匀。格数越多、边缘 bin 占的样本比例越小，比值才慢慢落回 1。

**增量 token 服从得很好**，N=256 时是 0.999 倍，N=16 也只有 1.05 倍。因为增量量程是由峰值速度定的，而峰值速度只有跑得最快的那几条轨迹才够得到——样本是不同尺度的混合，反而把量程填得比较匀。

这条差别本身不算大，但它是个提醒：**"格宽/√12"这个常用估算，对位置分词的误差会低估约一成。**

### 二、累积：一根递推，两个极端

误差怎么在 token 之间传，整个族谱可以用一根递推写完：

```
e_k = eta_k + rho * e_{k-1}
```

`eta_k` 是第 k 个 token 自己的量化误差，`rho` 是"解码时有多大成分在依赖自己的前缀"。rho = 0 表示每个 token 都被当前观测重新锚定，误差不传；rho = 1 表示 token 序列是计划的唯一载体，也就是 delta 分词——把每一步的增量 emit 出来，位置靠累加还原。

下表 N 固定 256，指数是对 k 从 16 到 128 做 log-log 最小二乘拟合的斜率：

| 方案 | rho | 拟合指数 | k=1 → k=128 增长 |
|---|---|---|---|
| 绝对 token，观测锚定 | 0 | -0.004 | 0.97 |
| 绝对 token | 0.9 | 0.004 | 2.60 |
| 绝对 token | 0.99 | 0.42 | 9.70 |
| 绝对 token，纯前缀 | 1.0 | 0.662 | 16.4 |
| delta token（含首 token） | 1.0 | 0.247 | 1.81 |
| delta token（只算增量） | 1.0 | 0.520 | 11.59 |
| 随机游走理论 | 1.0 | 0.5 | 11.31 |

**这里是整块最该记住的一行：末两行几乎重合，倒数第三行是假的。**纯增量的实测增长 11.59，理论 √128 = 11.31，指数 0.520——独立误差的随机游走律**精确成立**。但整条 delta 曲线拟合出来的指数只有 0.247、增长只有 1.81 倍，看上去像"累积很弱"。

它不弱，只是被一个**不增长的常数项**压住了。给曲线拟合幂律，而曲线里藏着一个加性常数，得到的指数没有意义。这个坑我原本准备用"周期性导致误差抵消"去解释，测完发现不是——两族轨迹的纯增量指数分别是 0.520 和 0.469，增长 11.59 和 11.26，都把理论值 11.31 夹在中间。**轨迹的频谱根本不进这一项。**

频谱进的是绝对 token 那几行。rho = 1 时，周期轨迹的指数是 0.662，带 5 个谐波的轨迹是 0.512。位置信号变化得越慢，相邻 token 的量化误差越正相关，累积就越**快于**随机游走；频谱一宽，相关性被拉平，指数落回 0.5 附近。所以 0.5 不是普适常数，它是"误差互不相关"这个前提的产物——**误差的相关性由信号的频谱继承而来**，只有增量的振荡形式会把它自动洗掉。

### 三、那笔常数：delta 分词要重付一次位置误差

delta 方案每个动作块还是要 emit 一个绝对 token 当锚点，位置才能还原。这一个 token 是按**位置量程**量化的，不是按增量量程——两个量程差 6.64 倍，格宽就差这么多。

| 量 | N=256 时 RMS |
|---|---|
| 单个 delta token 的量化误差 | 0.000133 |
| 锚点 token 的量化误差 | 0.00101 |
| 两者之比 | **7.45** |
| 锚点占块末误差的幅度比 | 71.7% |

锚点一个 token 就比 50 个增量 token 加起来还贵：块末总误差 0.00141，其中锚点贡献 71.7%。而且锚点是**每个动作块重付一次**，块越短越亏，永远摊销不掉。

于是 delta 分词看起来 7.45 倍精细，实际上：

- k=1 时 delta/绝对 = 1.05——第一个 token 的误差几乎就是锚点，两者打平，这一点自洽。
- k=50 时 delta/绝对 = **1.44**——累积把 7.45 倍的优势吃光之后还倒欠。

**结论：在"50 步一个块、256 个 bin"这个设定下，delta 分词比老老实实按位置分词更差，不是更好。**它省下的每一分分辨率，都被每块重付一次的锚点拿回去了。

### 四、多少 bin 才不成为瓶颈

判据是执行噪声地板：接触、负载、标定、伺服柔顺这些策略根本没有建模的东西。低于地板的那部分量化误差是白送的。地板取多大是个判断，所以我扫了一档：

| 执行噪声地板 | 观测锚定 | 自条件 rho=0.99 | delta token |
|---|---|---|---|
| 0.2% | 128 | 1024 | 256 |
| 0.5% | 64 | 512 | 128 |
| 1% | 32 | 256 | 64 |
| 2% | 16 | 128 | 32 |

**在 1% 这档，最悲观的解码方式要 256 个 bin，最乐观的只要 32 个。**256 正好是 RT-2 系的工业默认值。也就是说这个默认值不是拍脑袋，它对应的是"解码器很依赖自己前缀"这个悲观假设；如果你的策略每个 token 都能拿观测重新锚定，多出来的 8 倍 bin 全是浪费。

地板放宽一倍，需要的 bin 数就减半——四行都落在这个比例上，不过格子是按 2 倍档位扫的，所以 0.2% 那一行只能给到 128 这个上界。判据可以带着走：**需要的 bin 数 ≈ 2 × 量程 / (地板 × √12)，再乘上累积因子**；1% 档解出来是 24，表格的 32 是档位往保守方向取整的结果。

### 五、另一笔账：串行解码

上面全是精度，延迟是另一回事。下面没有做任何计时——比值是纯结构，不依赖机器：

| 动作块 (控制步) | AR 每块 token | AR 每块前向 | FM 每块前向 | 串行比 | AR 每控制步 | FM 每控制步 |
|---|---|---|---|---|---|---|
| 1 | 7 | 7 | 10 | 0.7 | 7 | 10.0 |
| 4 | 28 | 28 | 10 | 2.8 | 7 | 2.5 |
| 16 | 112 | 112 | 10 | 11.2 | 7 | 0.625 |
| 50 | 350 | 350 | 10 | 35 | 7 | 0.2 |

**最后两列里，AR 那个是常数 7。**每个控制步都要自己的 7 个 token，动作块拉长一点也不省——它省的是推理频率，不是每次推理的量。流匹配那一列相反，10 次前向出整块，块越长摊得越薄，50 步的块摊到每控制步只要 0.2 次。

这就是两条路线的分水岭：**自回归是"多步串行"，流匹配是"少步并行"。**同一个 50 步的动作块，自回归要 350 次串行前向，流匹配 10 次，串行比 35。OpenVLA 一类的实测推理频率在个位数赫兹，pi0 一类在几十赫兹 !CITE——量级差就是从这里来的。

精度上两条路反而谁也甩不开谁：量化误差压到 0.1% 量程以下只要有 256 个 bin，而流匹配那边多跑几步也能压到这个量级。**分水岭在延迟，不在精度。**

## 边界

- **解码器是显式误差递推，不是训练出来的网络。**`eta` 是真实量化误差（真实轨迹、真实量化器），但 `rho` 是我写下的假设，不是一个拟合出来的模型参数。本块量的是机制的价，不是任何已发布 checkpoint 的实测指标。这条在 results.json 的 `notes` 里也写了一遍。
- **rho = 1 对绝对 token 是退化情形**（解码时完全不看观测），列在表里是为了把族谱铺满，不是推荐配置。真实系统落在 rho = 0 到 0.99 之间，具体值取决于动作头怎么接条件。
- **轨迹是一维的。**真实动作块是 50 × 7 的张量。量化和累积是逐 token 独立发生的，维度只是把 token 数乘 7——延迟表里乘了，精度表里没乘，因为各维同分布时误差不会因为维度变多而变大。
- **1% 的地板是判断，不是测量。**换档位结论按 1/地板 缩放，表里给了四档。真正的争议不在这个数，而在"锚点算不算 delta 分词的固有成本"——那是设计选择：可以在每块开头 emit 一个绝对 token（本块的做法），也可以定期重锚，代价是分辨率被那些锚点稀释。
- **"绝对 token 不累积"是乐观假设。**它成立的前提是解码时观测足够强、能重新锚定每个 token。表里给了 rho = 0.9 / 0.99 / 1.0 三档，一档比一档差。
- **绝对量化的"超律"偏差是本族信号的形状造成的。**样本挤在量程两端（反正弦分布）才有 1.29 倍；换成填充更均匀的动作分布，这个倍数会掉回 1。量级会变，但"别用格宽/√12 估位置分词的误差"这个结论不会。
- **没有做任何计时。**延迟那一节只有前向次数和比值，没有毫秒。KV cache 让后续 token 的单步前向比首步便宜，但省的是每步的常数，不是步数——串行比 35 不受影响。

## 脉络

③-02 是少步并行，本块是多步串行，同一个频率错配的两种解法，延迟差 35 倍而精度同档 → 两条路都还留着开环的老问题 → ③-04 的 RTC 用 inpainting 把它补回来。
